# 双轨记忆服务与迁移判据

日期：2026-09-26。状态：用户批准实施双轨验证，尚未批准切换主库。

后续服务设计已补充：[跨设备与身份架构](memory-service-architecture.md)、[全文/向量/时间图处理](memory-retrieval-pipeline.md)、[P0–P6路线图](memory-roadmap.md)。新增能力仍为设计草案。本文件保留当前单主双轨与切换授权边界；下一轮阶段编号、量化目标与回退细节以路线图为准。

## 需求与边界

用户在 Kimi、Codex、Grok 和多台机器之间持续开发多个项目，需要跨工具找回决策、操作经验、事实来源和未完成事项。项目运行事实仍由代码、配置、日志及项目文档负责；记忆提供线索和来源，不替代当前检查。

Nowledge 保持正式写入和默认检索。los-memory 在 M3 保存单向影子副本，提供比较检索、按 ID 读取、同步状态。禁止双边独立修改同一事实；影子工具不暴露写入。既有 codex/claude/shared 数据库不参与镜像。

## 数据与服务

独立私有 SQLite 保存来源系统、space、源 ID、规范正文快照、内容摘要、同步时间及历史版本。只通过 Nowledge 按 ID 接口取正文，不把可能过期的搜索摘要当成正文。未明确标注项目的记录属于 unassigned，不从当前目录推断归属。

每轮分页发现活动 ID，按最旧验证时间优先限量刷新。同步失败保留上次成功快照，并报告失败；源端明确返回 404 或非活动状态才隐藏副本，清单缺失本身不能触发删除。不复制原始会话和凭证。初期只镜像 default space 的 durable memories，其他空间须独立授权和隔离。

M3 通过 SSH stdio MCP 暴露只读 search/get/status，不新增公网端口。客户端保留 Nowledge，额外安装 los-memory-shadow；结果带来源 ID、更新时间、影子标志。中文使用子串检索作为可靠基线；现有 hash embedding 不是学习式语义模型，不作为迁移质量证据。

M3 负责影子存储和定期同步；现有 NAS Nowledge 不变。M1 是客户端。M3 的性能余量足够，但休眠、断网与无人值守恢复仍须实测；若 14 天可用性不达标，再评估 NAS/常开小主机。数据库置于本机私有数据目录，禁止放进同步盘或 Git。

## 迁移门槛

1. 连续观察至少 14 天：成功刷新覆盖 100% 活动记录，正常网络下最长验证延迟不超过 24 小时；任务无静默失败，健康状态可观察。
2. 固定至少 40 个真实问题，覆盖中文子串、项目隔离、旧事实被修订、跨工具续接、明确删除和无答案；人工标注期望 ID。关键事实错误、越空间返回、过期正文冒充最新均为零；Top-5 命中率不低于 Nowledge 基线。
3. 验证断网恢复、重复同步幂等、并发同步互斥、编辑与撤回传播、备份恢复；恢复后 ID/版本摘要一致。单机损坏后可在 1 小时恢复服务，备份 RPO 不超过 24 小时。
4. 在 Kimi/Codex/Grok 新会话分别完成真实工具检索和按 ID 读取；SSH 可达条件下 p95 搜索小于 2 秒。客户端配置解析成功不算实际工具调用成功。
5. 完成正式写入 API、幂等键、修订/撤回契约、来源证据、导出恢复、Working Memory 生成和会话索引后，才能讨论取代 Nowledge。初期没有这些能力，不能宣布可迁移。
6. 门槛证据进入 docs/reports；用户确认主库切换窗口后冻结旧主库写入、最终增量校验、改客户端默认入口。保留旧库只读和回退窗口至少 14 天。

## 回退与后续

双轨回退只需禁用 los-memory-shadow MCP 和镜像定时任务；Nowledge 持续运行，用户正式记忆不丢失。恢复时继续使用同一源 ID，禁止重新导入成重复记忆。

后续顺序：基线评测、同步与恢复、统一身份和事件、混合检索、时间关系图、跨工具上下文、正式迁移。图谱 UI、自动融合与自动删除不是首阶段必需项。阶段门槛集中维护在 [路线图](memory-roadmap.md)。
