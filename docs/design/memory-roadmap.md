# los-memory 分阶段优化与迁移目标

日期：2026-09-26。状态：待实施路线图，阶段退出条件不是已完成结果。现有双轨功能、测试和资源测量分别见 [部署记录](../reports/2026-09-26-dual-track.md)、[资源评估](../reports/2026-09-26-resource-assessment.md)。架构见 [总体设计](memory-service-architecture.md) 与 [检索处理](memory-retrieval-pipeline.md)。

## 1. 排序原则

先证明范围与版本正确，再降低重复读取，随后增加统一身份/事件、全文检索、学习式向量、时间图和完整续接。最后才做主库切换。相邻阶段可以准备实验，但不能用后期功能掩盖前期数据错误。

每阶段必须产出可复现的输入、命令/协议、匿名结果、失败案例与回退步骤，记录到 docs/reports。下表是门槛驱动的依赖顺序，不承诺未经排期的日历工期。

| 阶段 | 目标 | 依赖 | 退出条件摘要 |
| --- | --- | --- | --- |
| P0 | 冻结基线与评测协议 | 当前双轨 | 40 个真实问题完成标注；范围/版本/来源可核对 |
| P1 | 优化镜像与运行可靠性 | P0 | 同等覆盖下流量下降 ≥70%；14 天观察；恢复演练 |
| P2 | 统一身份与规范事件服务 | 分段：契约无需前置；运行时 P0；跨设备/恢复 P1（见 §4 与 §10） | 跨设备幂等、范围授权、冲突/撤回、三客户端真实调用 |
| P3 | 全文与向量混合检索 | P2 | 对留出集语义题提升，精确/中文题不退化，资源达标 |
| P4 | 有证据的时间关系图 | P3；本体可提前设计 | 关系/历史题净增益，错误边与范围泄漏门槛通过 |
| P5 | 会话续接与上下文治理 | P2/P3；关系内容依赖 P4 | Kimi/Codex/Grok 跨设备/模型 handoff 成功，删除传播 |
| P6 | NAS34 候选主服务与迁移 | P1–P5 验收；可选图功能按批准范围 | 完整回归/恢复/资源观察通过，用户确认切换窗口 |

P4 的重型 Graphiti/外置图数据库是可选实验；若无收益，保留 P2 的版本关系与轻量证据边即可退出该路线。P6 必须记录放弃哪些可选能力，不能以阶段编号推断“所有图功能已实现”。

## 2. P0：基线与可重复评测

**交付**：私有评测语料、脱敏 case schema、按项目/时间冻结的数据集 manifest、Nowledge canonical ID/revision 对照、当前字面与 hash 基线。本轮资源样本作为起点，不是长期指标。

首批至少 40 个真实问题，按互斥主标签各 5 个：精确标识、中文短词、语义改写、项目隔离、事实修订/历史、关系多跳、跨工具续接、无答案/撤回。每例保存 query、principal/scope、as_of、应返回/禁返回的 ID+revision、支持来源和相关性 0/1/2 标注。

40 例用于发现故障，不用于调参后宣称泛化。P3 前扩到至少 120 例，开发集/留出集按项目或 thread 家族划分为 60/60，近重复不得跨集；每个关键类别在两侧都有覆盖，另列真正未见项目测试。固定快照与时间窗口，避免 Nowledge 仍在变化造成伪提升。

**门槛**：所有期望 ID 可按规范来源读取；越权、过期正文冒充最新、无证据批准均为零；当前实现失败案例必须可复现。搜索摘要与 canonical 内容不一致单独计数，不以语义相关度掩盖。

**停止条件**：来源版本和范围还无法确定时，停止后续模型排名调优，先修评测与记录契约。

## 3. P1：降低同步成本，证明持续运行

当前基线：1,655 条，每轮全清单约 4.67 MB，估计每天约 1.33 GiB / 33,696 请求；100 条/5 分钟轮转约 85 分钟。先补 24 小时实际流量/刷新/错误计数，再以同样本比较。

**工作包**：

1. 验证源 API 是否有可靠 updated_since、游标、revision/ETag、轻量 manifest；没有证据不能假设支持。
2. 有真实增量接口时采用变更游标 + 周期全量核对；新写回提示只在收到正式 Nowledge receipt 后触发按 ID 刷新，不能成为另一条正式写通道。
3. 没有增量接口时，将全清单发现与已知 ID 轮转分开。候选起点是每小时清单、每15分钟刷新100条，约4小时15分钟轮转，低写入样本估计日响应约140 MiB。参数须经过观测再调整，本轮没有修改现网周期。
4. 加入退避、时钟/睡眠恢复、同步锁、失败公平轮转、源实例识别、tombstone 传播、状态和告警；备份与日志保留策略有上限。

**门槛**：正常网络下活动 ID 覆盖100%，无永久饥饿；24小时实测响应字节下降 ≥70%、请求数下降 ≥50%；每条成功验证延迟 ≤24小时。fallback 新记录发现 ≤1小时；有可靠 receipt 提示的已知写入目标 ≤5分钟。覆盖和新鲜度优先于流量，不把更低频但漏数据算成优化成功。

连续14天报告每天失败数、最旧成功验证、来源变化与补齐、磁盘增量、客户端可达性。断网恢复不重复建记忆；恢复副本的 ID/revision/hash 一致。真正异机加密备份恢复达到 RPO≤24小时、RTO≤1小时。仅同机复制校验不足以通过此门槛。

**回退**：恢复上一份同步参数/发布，保留同一源 ID 与数据库，不回写 Nowledge。若发现增量漏事件，退回 canonical 周期核对并保留差异证据。

## 4. P2：统一身份、事件与正式存储契约

**交付**：独立 service.sqlite3、principal/grants/project registry、事件与修订表、receipt、冲突和撤回 API、事务 outbox、MCP/CLI 同一应用层、设备连接器。

新写入能力只在隔离测试空间和显式自研实验数据上验证；Nowledge 导入记录标记 imported_read_only。双轨期间真实正式记忆仍写 Nowledge，不能因为新 API 可用就产生两份独立主库。

**验收矩阵**：M1/M3/一个 Windows 或云节点，Kimi/Codex/Grok 三个客户端，至少两个实际服务商/网关路由、两个生成模型、两个 agent 身份和两个项目。按 pairwise 组合覆盖，再加“跨设备+跨模型+跨项目拒绝”联合边界，不假定测过一个客户端即全部通过。

至少完成：

- 同一事件重复提交100次仅一个语义提交；同幂等键不同内容返回冲突。
- 24小时离线 outbox 重放、乱序消息、进程中断恢复，无错误覆盖和无记忆复活。
- 两个 agent 基于同 revision 同时修改：一个成功，另一个409/待审；证据完整。
- 否定授权测试覆盖搜索/get/图边/缓存/bundle/export/history，越权结果与泄露计数为零；模型自报 owner/project 不扩大权限。
- 默认项目映射、repo改名、不同设备路径、同名 fork、agent-private、owner_shared 均符合预期。
- 三客户端新会话实际搜索/get、写入实验数据并查看 receipt；不能只验证工具发现。

**目标预算**：NAS34 候选环境中 1万 memory 的轻量服务空闲/常态 RSS≤256 MiB、短时≤512 MiB；3并发时写入持久化 p95≤500ms、ID读取≤200ms（不含模型推理）。如预算失败先定位全库加载、索引/连接、队列，不直接加 VM 内存。

**回退**：禁用新增 API/客户端入口；导入数据和实验事件有独立数据库可导出，不影响原 profiles 与 Nowledge。

## 5. P3：中文全文和学习式向量

**交付**：结构化全文投影、中文/标识符路由、一个锁定 fingerprint 的 embedding 实验、sqlite-vec 适配、RRF、规范回读、可选 rerank、generation 切换。外部模型只接收批准的数据类别。

按顺序做消融：现有子串 → FTS/中文 → FTS+向量 → 加 rerank。每个实验同时报告质量、完整性、时延、RSS、索引体积、模型调用/token；不能只报总平均。

**质量门槛**：留出集 Hit@5 不低于冻结的 Nowledge 基线；语义改写类 Hit@5 比纯全文提高至少10个百分点，精确标识/中文短词不降低；整体 nDCG@10 不降低。若样本过小，报告实际成功数与区间，不把单例增益当统计显著结论。选择权重只用开发集，留出集失败后若据其调参，必须重新建立留出集。

**正确性门槛**：所有最终结果都能回读当前授权的规范 revision；异步旧向量/删除/权限变化不能返回旧事实。embedding 更新的 generation 覆盖100%目标集合（或逐项列明不可处理项，不能宣布切换就绪），切换/回退不混模型空间。

**性能门槛**：以 10万实际 chunk、3并发、目标机器测热/冷两组；FTS p95≤300ms，混合端到端 p95≤2秒（包含 query embedding，单列网络部分），服务RSS≤512 MiB为初始目标。离线降级仍能查 ID/关键词。限制首轮远程嵌入实验不超过5,000 chunks，每 query 最多一次 embedding、一次可选 rerank；调用数/token必报，金额由实际提供商费率核算，扩大批量前给出具体预算。

**升级判据**：sqlite-vec 同范围精确检索经优化仍不满足性能/资源门槛，才进行 Qdrant 与可选 pgvector 对比。引入额外常驻服务必须证明收益并重新评估 NAS 物理内存余量。

## 6. P4：时间图与可解释关系

**交付**：小型实体注册表、带有效时间与来源的 relation_claims、别名/合并审查、SQLite有界遍历、历史查询和图结果解释。先用显式事实/已有来源关系，后测LLM抽取；不先全量构图。

实验限定一个批准项目/语料子集，抽样至少100条边人工标注；高风险决策、服务部署位置、权限关系必须100%有直接证据和正确范围。普通抽取边 precision≥95%，未达标的边留在候选区，不进入回答。

**收益门槛**：多跳/历史类 Hit@5 相比 P3 提升至少10个百分点且无关键错误；全文/语义类别不退化；图扩展额外 p95≤200ms（不含抽取），最多两跳/200边/50记忆。测取消别名合并、来源撤回、时间纠正后图与答案同步失效。

**停止条件**：如果图只增加复杂度没有稳定增益，保持轻量 supported_by/supersedes 关系，停止泛化实体抽取和独立图数据库。Graphiti、Neo4j 等不因路线图中出现就成为必选依赖。

## 7. P5：会话、Working Memory 与跨模型续接

**交付**：按任务/范围生成的 Context Bundle、带来源的 handoff、线程分页/原消息定位、敏感采集策略、衍生内容失效、按目标模型预算组装。已有原始会话导入必须先预览范围和容量，再单独批准历史回灌；能力开发不等于授权全量采集。

至少20组真实续接任务，覆盖三客户端、两设备、两生成模型、两项目、断网与冲突。由人工核对接手者是否找回正确目标、批准决策、代码revision和未完成动作；≥90%无需用户重复提供已记录关键事实，关键事实错误/越界为零。

默认上下文≤2,000 tokens，硬上限6,000；比较等预算的原始检索、摘要和图辅助 bundle。不能以更大上下文换得的成功率冒充检索提升。summary中可执行约束或批准必须有来源，prompt injection源文本只作为证据。

在线撤回后立即阻断规范读取；可重建投影/在线缓存目标5分钟内失效，Working Memory不能继续带旧结论。离线设备重连先接收撤回再发送旧事件；不可达缓存和备份的残留窗口要在回执中说明。

模拟两个实际服务商的限流/不可达，确认可降级到全文和排队，且不会绕开 egress policy。生成模型切换不重建向量；embedding切换按P3单独验收。

## 8. P6：NAS34 候选部署与主库迁移

P2开始可以在隔离路径对 NAS34 做小样本基准；正式候选服务/端口/认证部署前明确其数据与配置边界。最终优先 NAS34 VM 内单个 systemd 服务，不再新开VM，M3作为计算worker；若 NAS 可用内存或恢复条件不满足，则继续M3或评估独立常开小主机。

**生产候选门槛**：

1. 完整配置连续14天运行，空闲、3客户端并行、导入、重索引分开报告；无 OOM/持续swap，物理NAS available目标>2GiB。完整会话规模的预算重新实测，不沿用小影子32MiB结论。
2. 全部必选能力的留出评测通过；历史版本、项目/空间过滤、撤回均无关键错误。可选图功能未通过可关闭，但在切换清单明确。
3. 异机备份恢复 RPO≤24h / RTO≤1h，先恢复规范+全文的降级服务；完整向量/图重建时间另报。恢复后重放擦除清单，防止被删除记忆复活。
4. 当前主库与候选库按规范ID/revision/正文摘要/作用域/生命周期核对，不仅比条数；线程、Working Memory 和有意不迁移项目逐项有映射/例外清单。
5. 用户确认切换窗口与最终迁移范围。冻结 Nowledge 正式写入、补齐最后增量、记录 cutover epoch、只启用一个主写入口；禁用旧写入口，而不是只改默认搜索。
6. 切换后保留 Nowledge 只读至少14天。若回退，先冻结新库写入，导出切换后的规范事件并显式映射/验证回灌旧库，再恢复旧库写入；不能简单切URL导致新写入丢失。

主写切换后停用 Nowledge→los-memory 的旧增量导入，避免重新导入旧状态；历史来源映射保留。模型与设备凭据、加密备份、worker lease和fencing均纳入恢复清单。

## 9. 指标定义与证据格式

- Hit@5：存在至少一个人工标注相关答案的查询中，前5条命中所需ID/revision的比例；与需要多个事实的 Recall@5 分开。
- Recall@K：应返回的相关证据集合在前K条中的覆盖比例；多跳题同时报告路径完整性。
- nDCG@10：按固定0/1/2相关性标注评估排序；不靠模型自评分作为唯一标注。
- Version correctness：返回版本符合 current/as_of 语义的比例；关键错误单独列出，不由平均值稀释。
- Grounding coverage：结论可回读到获准source revision/span的比例；来源不存在、被撤回或无支持片段均不计通过。
- Isolation：跨principal/space/project/agent_private的负向测试，必须零泄漏；过滤后数量不足也要报告召回损失。
- Freshness：源确认写入到规范提交、FTS-ready、semantic-ready、graph-ready分别计时；断网窗口单列。
- 资源/成本：服务进程、worker、MCP bridge、宿主及VM分开；请求/响应字节与token用量不等价；提供商成本按渠道标明。

每份阶段报告包含：git revision + dirty source摘要、schema/index/模型/分词器版本、硬件与并发、数据集hash/数量/时间、命令、冷/热次数、成功/失败总数、p50/p95、分类质量、退化路径、费用口径、结论和回退。原始会话、凭据与私有语料不能提交到Git。
