# 自建 memory 与 NAS34 资源评估

实测时间：2026-09-26 13:32–13:37 CST。范围：M3 影子服务、NAS34 Linux 虚拟机中的 Nowledge、Z4Pro 物理宿主。只读采样；同步负载测试写入 M3 临时数据库副本，结束后清理，没有修改主库或现网配置。

## 结论

当前 los-memory 影子服务很轻，NAS34 有能力承载；无需因为算力把字面检索/SQLite 服务固定在 M3。现阶段保留 M3 双轨验证，后续通过迁移门槛后优先考虑 NAS34 常驻服务，M3 承担批处理或可选模型计算。这个部署建议尚未执行。

不能将影子的几十 MiB 与 Nowledge 的几 GiB 直接解释为同功能优化比例：影子只处理 1,655 条 durable memories，Nowledge 还存储 141,716 条 thread_messages，并有图数据库、多个搜索索引和其他工作流。

M3 为 36 GiB / 11 CPU，磁盘剩余约 308 GiB；当前 swap 已用约 2.04 GiB，因此也不能把总内存直接当成空闲额度。影子进程由每个 stdio MCP 连接按需启动；没有客户端连接时不需要常驻 MCP 进程。当前采样没有常驻影子 MCP，以上内存是实际探针工作进程值。三个并行客户端粗估约三份 Python 工作集，约百 MiB 量级，仍须以实际连接数测量；不能只算一份服务器进程。

NAS34 是 Z4Pro 内的 ubuntuVm：配置 10 GiB、3 vCPU、开机自启；宿主 qemu RSS 约 9.39 GiB。虚拟机内 4.7 GiB available 与物理机 2.4 GiB available 属于嵌套口径，不能相加。不建议继续增加虚拟机内存或在同一 NAS 上同时放本地大模型。

## Nowledge 内存由什么构成

cgroup memory.stat 实测 anon 3.31 GiB、file 126.5 MiB、kernel 11.8 MiB；主要不是可回收文件缓存。服务自身 swap=0，OOM 计数为零。虚拟机/宿主已经使用 swap，不等于 Nowledge 当前正在发生换页压力。短采样不足以判断泄漏，需看稳定负载下 24–72 小时趋势及导入后是否回落。

内容库另有 708 个 content_documents、287 个 content_chunks、685 个 thread_content_generations。数据目录中保留了 failed 搜索索引和旧 corrupt WAL 文件名；这只能证明有历史残留，不能据此宣布当前损坏，本轮未删除。

## 当前同步的主要浪费

当前清单 API 返回完整正文，而非仅 ID。实测一轮清单需 17 次 HTTP 请求、4,670,388 字节、3.11 秒；随后再按 ID 验证 100 条。每条规范快照平均 2,819.7 字节。

按现有每 300 秒一轮估算：

- 每天 288 轮，约 33,696 次 HTTP 请求。
- 每天响应正文约 1,360 MiB，即 1.33 GiB；不含协议开销，也不等于公网收费流量。
- 同步 CPU 约 0.561 / 300 = 单核平均 0.19%，墙钟占空约 2.1%。
- 1,655 条轮转至少 17 轮，约 85 分钟；每 5 分钟执行不代表每条记录 5 分钟内刷新。

这些是按本次样本计算的规划估计，不是整日遥测。优先改进源端 updated-since/cursor、轻量 manifest 或变更版本；若 API 不支持，应分开低频全清单对账与有界轮转刷新，并明确新记录发现/修订延迟。不能为节省请求而改用已知可能过期的搜索摘要。

影子现有 3,323 个 revision，其中包含本轮摘要算法从全响应切换为排除展示 time 的一次历史膨胀，并非用户事实真的变更了两倍。历史记录没有清理。后续需按事实修订速率观察增长，不能拿当前一次性膨胀直接推算月增长。

## 容量预算与放置建议

1. 当前阶段：继续 M3 影子、NAS34 Nowledge。M3 的休眠和登录用户 launchd 恢复仍需观察；不因资源测量立即切换主库。
2. 轻量正式服务候选：NAS34 VM 内单独 systemd 服务，先以 1 vCPU、256–512 MiB 规划额度和 1 GiB 工作空间起步。额度属于建议，不是已施加的限制；不再新建额外 VM。SQLite/检索/来源版本由常驻服务承担。
3. 完整替代阶段：纳入 14 万条消息后必须重新测量。当前搜索每次扫描并反序列化全部记录，时间随正文规模增长；需数据库检索索引、限量候选和分页，不能将当前 32 MiB/19ms 外推为完整服务承诺。
4. 学习式 embedding、rerank、图谱提炼应按需调用远程模型或 M3 worker；不默认在 N97/16 GiB NAS 加载常驻模型。若迁移后停止 Nowledge，可能释放其几 GiB 工作集，但在实际停止和测量前不能把它计入可用容量。
5. 验收增加资源曲线：空闲、三客户端并行、增量导入、全库重索引分别测 RSS/PSS、CPU、IO、延迟和宿主 available；参考预算为轻量服务稳定 RSS <256 MiB、短时 <512 MiB，保持物理宿主 available >2 GiB 且无持续 swap in/out。最终阈值随完整能力评测调整。
