# W-01 P0 评测基线：影子 vs Nowledge 主库

日期：2026-10-07。范围：40 例私有检索用例 × 两个后端（M3 影子快照 / Nowledge 主库默认搜索）。只读。
harness：`scripts/shadow_eval.py`。私有语料：`~/.local/share/los-memory-shadow/eval/cases.jsonl`（**不进 Git**）。

这是路线图 P0 的第一个门槛产物。它的用途是**发现故障**，不是宣布"影子已经够用"。

## 0. 方法

- **影子后端**：从 M3 取一致性快照（SQLite backup API，非拷文件），在本地副本上用 `memory_tool.shadow.search_detailed` 检索，`limit=20`。
- **Nowledge 后端**：`nmem memories search "<query>" -n 20 -j`，即主库的**默认（语义）搜索**。
- **项目范围**：`--scope native` 才把用例的 `scope.project` 传成真过滤；`--scope none` 不传（默认）。两个模式都跑了，因为两者回答的是不同问题（见 §4）。
- **指标**：Hit@5、Recall@5、nDCG@10（0/1/2 相关性）、isolation 违规数（命中 `forbidden` 的条数）。`no_answer` 类不计入命中率（`expected` 为空），只检查是否错误返回了近邻记录。

复现：

```sh
python3 scripts/shadow_eval.py --cases ~/.local/share/los-memory-shadow/eval/cases.jsonl \
  --shadow-db ~/.local/share/los-memory-shadow/eval/snap-postfix.sqlite3 \
  --backend both --limit 20 --scope native --no-baseline --out /tmp/eval-native.json
```

**语料来源的诚实声明**：40 例查询是**基于真实镜像记录人工撰写**的，不是从真实用户会话里采集的。`expected` 里的 `source_id` 全部是真实存在的记录（逐条校验过：0 个缺失、0 个伪造），但**"用户真的会这样问吗"没有被验证**。这是与迁移门槛 2「固定 40 个真实问题」之间的已知缺口，见 §6。

## 1. 结论（先看这一节）

1. **在这个用例集上，影子的总体 Hit@5 明显高于 Nowledge 的默认搜索**（0.771 vs 0.200）。**但这个差值不能读成"影子好 4 倍"**——用例是照着语料写的，天然偏向字面匹配，而 Nowledge 的默认入口是语义搜索。请看 §6 的口径警告。
2. **两个后端在"语义改写"类上都是 0.000**。这一类比**没有区分度**，不能拿来当 P3 的门槛，必须先重新设计（§5）。
3. **应用项目过滤后，影子的跨项目泄漏为 0**（`forb@20 = 0`）；不加过滤时影子命中 8 条 forbidden —— 那是"没做过滤"的必然结果，不是隔离失效（§4）。
4. **Nowledge 在 `no_answer` 类上有 2 条违规**（把"不该有答案"的问题答成了近邻记录）；影子 0 条。
5. 影子在**精确标识**上 5/5 全中，而这正是 Nowledge 默认搜索最弱的一类（5 例中 4 例未命中）——两者失败的方向**相反**，这本身就是 P3 混合检索的论据。

## 4. Isolation（门槛要求"越权结果为零"）

| 模式 | 影子 forbidden@20 | 影子 forbidden@5 | Nowledge forbidden@20 | Nowledge forbidden@5 |
| --- | --- | --- | --- | --- |
| `--scope none`（不传项目过滤） | 8 | 3 | 5 | 4 |
| `--scope native`（项目过滤生效） | **0** | **0** | 2 | 2 |

**只有 native 那一行在测隔离。** none 那一行是"没做过滤"的必然结果，把它读成隔离缺陷是误读——这正是本报告要写清楚的地方。native 下影子 0 违规；Nowledge 的 2 条违规都出现在 `no_answer` 类（对"不该有答案"的问题返回了近邻记录，如 `Kubernetes 集群部署的副本数是多少` 返回了 `Docker 生产部署: PG/Redis 硬化 6 坑`）。

## 5. 这一轮暴露的夹具缺陷

1. **`semantic_paraphrase` 无区分度**：两个后端都是 0.000。可能原因有二，本报告**无法区分**：① 两个后端都不具备语义能力（Nowledge 默认搜索的表现支持这一读法）；② 这 5 例期望的记录在这 5 个问法下本来就不可达，属于**不可答题**。P3 之前必须重做这一类：先把"人看着问法能从语料里答出来吗"逐例标注，再决定是留作 P3 门槛还是降级为说明性样例。
2. **用例来源是语料而非真实提问**，因此偏向字面。要满足门槛 2 的字面要求，需要从真实会话里采集 40 个问题（DSH 会话索引里有候选），而不是继续照着语料写。
3. **`fact_revision` 只测了"当前版本要返回"，没测"旧版本不该冒充最新"**——影子 API 没有 revision 概念，所以 `version_correctness` 输出为 `N/A`，本次**没有**编造这个数字。真正测版本要等 L2（P2）的 `base_revision`/409 契约。
4. n=40（35 计分）**不做统计显著性结论**。P3 前按路线图扩到 120 例、开发/留出 60/60，且近重复不得跨集。

## 6. 口径警告（最重要的一条）

> **不要用"影子 0.771 > Nowledge 0.200"来论证"可以替代 Nowledge"。**

三条理由：

1. **循环性**：用例是照着影子所镜像的语料撰写的，`expected` 也来自同一语料。这天然奖励字面匹配，而字面匹配正是影子的实现方式。要让这个比较有意义，语料必须来自**独立于语料本身的真实提问**。
2. **入口不对称**：Nowledge 有语义、字面、按 ID、按空间等多条路径，本报告只打了它的**默认搜索**一个入口。这是"默认入口"的比较，不是"能力上限"的比较。
3. **量级可信、末位不可信**：两边都存在非确定性（Nowledge 语义搜索；影子排序含 `verified_at` 平局打破）。**结论只应建立在"影子在字面类明显更强、两边在语义类都失败"这个量级判断上。**

## 7. 对路线图的直接输入

- **P1**：不受本报告阻塞，继续按 §5.5.1 的三层同步方案推进。
- **P2**：`version_correctness = N/A` 是 P2 存在的理由之一——修订/冲突契约一落地，这一列才有数字。
- **P3**：优先级应是"补齐语义 + 保住字面"，而不是"用向量替换全文"。本报告的直接证据是：字面类影子已经 1.000，而语义类是 0.000；P3 的目标是让语义类动起来且**字面类不退化**。
- **门槛 2 的判据需要改写**："Top-5 不低于 Nowledge 基线"在字面类上已经满足，在语义类上双方都是 0（无意义）。建议改为**按类别分别判定** + **基线入口显式写清是哪一个**（默认搜索 / 按 ID / 语义混合）。
