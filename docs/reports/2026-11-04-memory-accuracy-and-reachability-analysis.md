# 记忆的准确性与可触达：处理策略分析（2026-11-04）

状态：**分析报告 + 决策建议**。本文回答一个问题：在"尽量维持记忆的**准确性**、同时保证**能触达**"这两个
目标下，这批记忆该怎么处理才合理。它同时**更正** 2026-11-03 基线里一个错误的度量结论（§1）。

配套：[记忆整理与清理方案](../design/memory-hygiene-and-consolidation.md)、
[2026-11-03 基线](2026-11-03-memory-hygiene-baseline.md)（其 §3 的轨道重复行以本文为准）。

## 0. 结论先行

1. **"31.3% 冗余"不存在**。14 组"重复轨道"是**符号链接别名**（两条路径指向同一 inode），真重复只有
   **2 条（0.04%）**。所以"去重"不是杠杆；按旧结论去删别名目录，会让那个 cwd 的项目记忆**立即不可达**
   ——正好违背用户的核心目标。
2. **真正的两个缺口是可寻址性与有效性覆盖**：`addressability = 2.9%`（151/5,227 条有 `[id:…]`）、
   `validity = 0.06%`（只有 3 条参与"取代/失效"关系）。前者让"更新、合并、引用"无法机械执行，
   后者让"still active"这个状态不携带信息。
3. **可触达的瓶颈不在库里，在注入面**：25 个 track / 845 条 / 883 KB 全部走摘要注入；
   按 80–120 字符/条估算约 8.8–10 万字符 ⇒ **25–30k tokens 的固定开销**，且每行分到的注意力极低
   （context rot）。所以可触达要靠**选择算法**（按需检索、按价值密度填充预算），不是靠清库。
4. **处理顺序**（按边际收益/风险）：①写侧强制结构（id + supersedes）②回填 id（机械、可逆、解锁全部）
   ③上下文选择（ACT-R 激活度 + 背包）④取代积压只做能机械判定的 **3%（4/131）**，其余靠惰性修复
   ⑤`daily/` 先摘要后 TTL。

## 1. 更正：被误报的 31.3%

| 指标 | 2026-11-03 报告 | 2026-11-04 复核 | 差 |
| --- | --- | --- | --- |
| 轨道数 | 135 | **122**（+14 条别名路径） | −13 |
| 条目数 | 7,594 | **5,227** | −2,367 |
| "轨道重复" | 14 组 / 2,378 条 | **0 组 / 0 条** | 全部撤回 |
| 真重复（独立 inode） | 2 | **2** | 不变 |

**错因**（三条，缺一不可）：①`discover_tracks` 用 `Path.iterdir()`，它**跟随**符号链接；
②"同一份记忆"的身份用了**路径**而不是 `(st_dev, st_ino)`；③没有负向控制去区分"别名"与"真复制"。

**证据**：`projects/faab4b6033b2` 是指向 `projects/2d4994d462af` 的 symlink（`ls -ld` 可验证），
两条路径的 `st_ino` 相同、`st_nlink` 为 1、`du` 为 0 KB。`find projects -maxdepth 1 -type l` 命中 **7 个**，
对应 7 组（MEMORY + KEY 各一条）＝ 14 条别名路径。

**修法**（已落地，`scripts/hygiene_scan.py`）：`resolve_aliases()` 按 `resolve()` 后的真实路径分组，
**真路径优先做 canonical**；别名进 `metrics.alias_tracks` 与 `aliases[]`；`track_duplicate` 只对
**不同 inode** 的同一内容集触发（负向控制：`shutil.copyfile` 造的真复制必须仍然报）。新增 3 例测试。

这条更正本身就是一条纪律：**"重复"必须由身份（inode/内容 hash）判定，不能由路径出现次数判定**。
同一份报告里"条目内容 hash 相同"的判断是对的，错的是把"两条路径指向同一文件"当成了两份数据。

## 2. 两个目标的形式化

**准确性 A**：`A = P(返回的事实在查询时刻仍然成立 | 该事实被返回)`。

- 结构代理：`A0 = 1 − stale_candidates / entries`，`stale_candidate` = **有后继声明、自身仍 active**。
  现状：131 条自述取代无机械边（`claim_without_edge`），占 2.5%；其中只有 **4 条**能在同轨找到被引用的
  目标（引号短语命中），**10 条**带引号短语、其余 121 条是无指代的叙述（"上次那个结论""此前一条"）。
- 真值需要抽样：每周抽 30 条"当前状态类"问题，判"引用的是不是最新版本"，报 `A` 的点估计与区间。
  平均分不够——必须逐项列出"过期事实被当最新"这类错误。

**可触达 R**：`R = P(某条需要的记忆在预算 B 内被检索到)`。

- `R1 = Hit@k / MRR`（冻结需求集；本仓已有 B0 冻结集与 `shadow_eval.py` 这套仪器）。
- `R2 = addressability`：能否被**名字**定位（可 supersede/可引用）；现状 2.9%。
- `R3 = scope coverage`：能否被 project/kind 过滤到（本仓 B1 已量到 25.49%、上限 45.65%）。
- `R4 = context_face_tokens`：固定注入开销；现状 845 条 / 883 KB（摘要口径约 25–30k tokens）。

**两者不是同向的**：

| 动作 | 对 A | 对 R | 备注 |
| --- | --- | --- | --- |
| 删掉"看似重复"的别名目录 | 0 | **↓↓**（该 cwd 立刻读不到） | 上一轮差点这么做 |
| 删掉真正重复的条目 | 0 | 0 | 只省预算，收益极小 |
| 退役已过时条目 | **↑** | 0（它本来就不该被召回） | 需要 validity |
| 回填 id | 0 | **↑**（可被引用/可被合并且不冲突） | 机械、可逆 |
| 全量摘要注入 | ↓（噪音） | ↓（预算被摊薄） | 需换成按需选择 |
| daily 直接删 | ↓（丢证据） | ↓↓ | 应先摘要 |

## 3. 理论：哪一条在什么条件下才成立

| 理论 | 关键式/机制 | 何时才相关 | 对本语料的裁决 |
| --- | --- | --- | --- |
| **BM25 / IDF 稀释** | `idf = ln((N−df+.5)/(df+.5))`；重复文档使 df 翻倍。N=7600 时 `ln7600−ln3800≈0.69`，稀有词权重降约 8% | **仅当重复内容真的进了索引** | **不适用**（重复≈0）。上一轮"去重能提升召回"的暗示撤回 |
| **AGM 信念修正 / JTMS** | 撤回要留 justification，删除不可逆；`supersedes` 就是 justification 边 | 事实会演化、需要解释"为什么变了" | **采用**：唯一同时保住 A 与历史的机制 |
| **双时间建模（Zep）** | `valid_at/invalid_at`（世界时间）vs `created_at/expired_at`（记录时间） | 需要"当时是什么"的点时间查询 | **采用 valid 区间**；`as_of` 查询延后 |
| **遗忘曲线（Ebbinghaus / 幂律）** | 指数 `exp(−t/S)` vs 幂律 `t^−d`；S 随成功召回增长（间隔效应）。MemoryBank 把 `−t/(5S)` 写成 `(−t/5)·S`，越常召回越早删 | 需要"让不重要的东西淡出" | **只用于排序与复审排期，永不用于删除**；公式带单调性测试 |
| **ACT-R 基础激活** | `A_i = ln(Σ_j t_j^{−d})`，`t_j` = 第 j 次召回距今时间，d≈0.5 | 需要同时编码"常用"与"最近" | **采用**为上下文选择的打分（比指数衰减更贴合间隔效应） |
| **上下文即缓存 / 预算背包** | `max Σ v_i x_i s.t. Σ s_i x_i ≤ B`，`v_i/s_i = P(need)·importance/size`；贪心近优 | 注入面有硬预算 | **采用**：替代"全量摘要注入" |
| **信息论去重** | 重复信息量≈0 bit 但占预算 | 重复占预算时 | 现在约占 0.04%，**不是杠杆** |
| **实体解析 / 别名** | 身份按内容/id，路径只是定位提示（与 `memory-retrieval-pipeline.md` §2.1 一致） | 同一实体多个名字 | **采用**：路径降级为 alias，id 升为身份 |
| **反思式压缩（Generative Agents）+ 可还原压缩（Manus）** | 压缩必须保留指针/锚点，否则不可逆 | 长尾证据（daily）需要瘦身 | **采用**：摘要带稀有锚点，能回读原文 |

一句话：**准确性靠"撤回"，可触达靠"选择"**。把这两件事混成一个"清理"动作，就会重演 MemoryBank 的错误
（用衰减去删除）或我上一轮的错误（用路径计数去判重复）。

## 4. 对三项待拍板的回答

| 问题 | 建议 | 依据 | 反着做的代价 |
| --- | --- | --- | --- |
| 14 组"重复轨道"怎么办 | **不删、不合并**；登记为 alias 并加门禁（已实现） | 同 inode = 一份数据两个名字；写穿任一路径都落到同一文件 | 删掉别名 → 该 cwd 项目记忆不可达（A 不变、R 断崖） |
| 131 条自述取代 | **只处理能机械判定的 4 条**（引号短语 + 同轨 + 时间更早 + 目标仍 active），人工批量确认；其余**不做**，改为写侧强制 `[supersedes:id]` + 惰性修复（旧条目被检索到时才修） | 可机械判定率 3%；错误 deprecate 直接伤 A | 按文本批量退役 → 误退役（A 反而降，且不可解释） |
| `daily/` 是否设 TTL | **先摘要、后 TTL**：30 天原文 → 月度摘要（含稀有锚点与原文指针）→ 原文进归档目录 | 压缩必须可还原；日刊是证据面 | 直接删/直接压 → 丢证据且不可回读（R 不可逆下降） |

**惰性修复**值得展开：不必一次修完 131 条。命中一条"旧条目被检索到且它有个更晚的兄弟条目"时，才生成一条
`supersede` 提案。按使用频率付费，避免了为 90% 从不被检索的条目付人工成本 —— 这正是 ACT-R 激活度该管的事，
而不是"按日期全量扫"。

## 5. 排序（边际收益/风险）

| 步 | 动作 | 目标 | 风险 | 回滚 |
| --- | --- | --- | --- | --- |
| P0（已完成） | 测量修正：alias 身份、coverage、context_face；计划器不再产出假提案 | 先把尺子修对 | 无 | 删脚本 |
| P1 | **回填 `[id:…]`**（插件已支持 `legacyIdFor = sha1(内容)`，确定性、幂等） | R2 2.9%→100% | 极低（只加身份，不改正文语义） | 去掉 id 前缀 |
| P2 | **写侧强制结构**：新增记忆必须带 `project` 与（若在取代）`supersedes` | A 的抗退化 | 写入体验变严 | 放宽为警告 |
| P3 | **上下文选择**：ACT-R 激活度打分 + 背包填充（替代全量摘要注入） | R4 / 注意力 | 中（要测 Hit@5 不退化） | 回退到全量摘要 |
| P4 | 取代积压 4 条 + 每周抽 30 条准确性抽样 | A | 低 | 台账回退 |
| P5 | `daily` 月度摘要 + 归档 | 长期预算 | 中（摘要必须可回读） | 保留原文 |
| P6 | `as_of` 点时间查询（双时间） | 历史类问题 | 低 | — |

P1 之所以排在 P2 前面：**没有身份就没有结构**。131 条里只有 2 条带 `[supersedes:]`，而插件在没有 id 的条目上
做 `deprecateEntry` 时会**就地补发 id** —— 说明"先有 id"是这套机制的隐含前提，缺它会让每一次退役都产生
"新 id"，跨设备/跨版本无法对齐。

## 6. 度量与门禁（每次改动都要过）

```bash
python3 scripts/hygiene_scan.py --corpus dsh-md:~/.dsh/memories          # coverage / context_face 必须被报出
python3 scripts/hygiene_cleanup.py plan                                 # actions 应为 0（或极少数、全部可解释）
python3 scripts/hygiene_scan.py --self-test && python3 scripts/hygiene_cleanup.py self-test
python3 -m pytest tests/unit/test_hygiene_scan.py tests/unit/test_hygiene_cleanup.py -q
```

- **无回归门**：冻结需求集 Hit@5 变化 ≤1pp；准确性抽样中"过期当最新"计数不得上升。
- **预算门**：`context_face.chars` 不得随清理上升；每加一条摘要必须能指出它替掉了什么。
- **沉默即告警**：扫描/计划作业 6h 无新增即 `hygiene_stale`（本仓已有两次"探针静默被读成正常"的教训）。

## 7. 明确不做的

- 不以"库变小"为目标（空间轴已有 `retention-policy.md`，且收益一次性）。
- 不用文本相似度做退役判据（本仓 87/87 回测失效）。
- 不做无人确认的批量淘汰；不原地改写旧正文；不删 `daily/` 证据。
- 不把"别名"当"重复"，也不为省事去删别名目录。

## 8. 未决

1. ACT-R 的 `last_used_at/use_count` 目前**完全缺失**（没有读侧埋点）。P3 之前必须先埋点，否则激活度只能
   用写入时间近似 —— 那会把"常被引用但很久没被写入"的条目误判为冷。
2. 准确性抽样由谁判定（人 / 另一个模型 / 结构化规则）需要定；判定器必须与"被判定对象"不同源。
3. P2 的"强制"是硬失败还是警告：建议先 4 周警告 + 计数，再转硬失败（沿用本仓"先量后定"的节奏）。
