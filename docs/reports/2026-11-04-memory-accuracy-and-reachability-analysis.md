# 记忆的准确性与可触达：处理策略分析（2026-11-04）

状态：**分析报告 + 决策建议**。本文回答一个问题：在"尽量维持记忆的**准确性**、同时保证**能触达**"这两个
目标下，这批记忆该怎么处理才合理。它同时**更正** 2026-11-03 基线里一个错误的度量结论（§1）。

配套：[记忆整理与清理方案](../design/memory-hygiene-and-consolidation.md)、
[2026-11-03 基线](2026-11-03-memory-hygiene-baseline.md)（其 §3 的轨道重复行以本文为准）。

## 0. 结论先行

1. **"31.3% 冗余"不存在**。14 组"重复轨道"是**符号链接别名**（两条路径指向同一 inode），真重复只有
   **2 条（0.04%）**。所以"去重"不是杠杆；按旧结论去删别名目录，会让那个 cwd 的项目记忆**立即不可达**
   ——正好违背用户的核心目标。
2. **真正的两个缺口是可寻址性与有效性覆盖**：`addressability = 2.9%`（151/5,227 条有 `[id:…]`）、
   `validity = 0.06%`（只有 3 条参与"取代/失效"关系）。前者让"更新、合并、引用"无法机械执行，
   后者让"still active"这个状态不携带信息。
3. **可触达的瓶颈不在库里，在注入面**：25 个 track / 845 条 / 883 KB 全部走摘要注入；
   按 80–120 字符/条估算约 8.8–10 万字符 ⇒ **25–30k tokens 的固定开销**，且每行分到的注意力极低
   （context rot）。所以可触达要靠**选择算法**（按需检索、按价值密度填充预算），不是靠清库。
4. **处理顺序**（按边际收益/风险）：①写侧强制结构（id + supersedes）②回填 id（机械、可逆、解锁全部）
   ③上下文选择（ACT-R 激活度 + 背包）④取代积压只做能机械判定的 **3%（4/131）**，其余靠惰性修复
   ⑤`daily/` 先摘要后 TTL。

## 1. 更正：被误报的 31.3%

| 指标 | 2026-11-03 报告 | 2026-11-04 复核 | 差 |
| --- | --- | --- | --- |
| 轨道数 | 135 | **122**（+14 条别名路径） | −13 |
| 条目数 | 7,594 | **5,227** | −2,367 |
| "轨道重复" | 14 组 / 2,378 条 | **0 组 / 0 条** | 全部撤回 |
| 真重复（独立 inode） | 2 | **2** | 不变 |

**错因**（三条，缺一不可）：①`discover_tracks` 用 `Path.iterdir()`，它**跟随**符号链接；
②"同一份记忆"的身份用了**路径**而不是 `(st_dev, st_ino)`；③没有负向控制去区分"别名"与"真复制"。

**证据**：`projects/faab4b6033b2` 是指向 `projects/2d4994d462af` 的 symlink（`ls -ld` 可验证），
两条路径的 `st_ino` 相同、`st_nlink` 为 1、`du` 为 0 KB。`find projects -maxdepth 1 -type l` 命中 **7 个**，
对应 7 组（MEMORY + KEY 各一条）＝ 14 条别名路径。

**修法**（已落地，`scripts/hygiene_scan.py`）：`resolve_aliases()` 按 `resolve()` 后的真实路径分组，
**真路径优先做 canonical**；别名进 `metrics.alias_tracks` 与 `aliases[]`；`track_duplicate` 只对
**不同 inode** 的同一内容集触发（负向控制：`shutil.copyfile` 造的真复制必须仍然报）。新增 3 例测试。

这条更正本身就是一条纪律：**"重复"必须由身份（inode/内容 hash）判定，不能由路径出现次数判定**。
同一份报告里"条目内容 hash 相同"的判断是对的，错的是把"两条路径指向同一文件"当成了两份数据。

## 2. 两个目标的形式化

**准确性 A**：`A = P(返回的事实在查询时刻仍然成立 | 该事实被返回)`。

- 结构代理：`A0 = 1 − stale_candidates / entries`，`stale_candidate` = **有后继声明、自身仍 active**。
  现状：131 条自述取代无机械边（`claim_without_edge`），占 2.5%；其中只有 **4 条**能在同轨找到被引用的
  目标（引号短语命中），**10 条**带引号短语、其余 121 条是无指代的叙述（"上次那个结论""此前一条"）。
- 真值需要抽样：每周抽 30 条"当前状态类"问题，判"引用的是不是最新版本"，报 `A` 的点估计与区间。
  平均分不够——必须逐项列出"过期事实被当最新"这类错误。

**可触达 R**：`R = P(某条需要的记忆在预算 B 内被检索到)`。

- `R1 = Hit@k / MRR`（冻结需求集；本仓已有 B0 冻结集与 `shadow_eval.py` 这套仪器）。
- `R2 = addressability`：能否被**名字**定位（可 supersede/可引用）；现状 2.9%。
- `R3 = scope coverage`：能否被 project/kind 过滤到（本仓 B1 已量到 25.49%、上限 45.65%）。
- `R4 = context_face_tokens`：固定注入开销；现状 845 条 / 883 KB（摘要口径约 25–30k tokens）。

**两者不是同向的**：

| 动作 | 对 A | 对 R | 备注 |
| --- | --- | --- | --- |
| 删掉"看似重复"的别名目录 | 0 | **↓↓**（该 cwd 立刻读不到） | 上一轮差点这么做 |
| 删掉真正重复的条目 | 0 | 0 | 只省预算，收益极小 |
| 退役已过时条目 | **↑** | 0（它本来就不该被召回） | 需要 validity |
| 回填 id | 0 | **↑**（可被引用/可被合并且不冲突） | 机械、可逆 |
| 全量摘要注入 | ↓（噪音） | ↓（预算被摊薄） | 需换成按需选择 |
| daily 直接删 | ↓（丢证据） | ↓↓ | 应先摘要 |

## 2.1 判定分级：按场景决定"谁来确认"（2026-11-04 定稿）

用户指定的规则：**有数据/代码能直接确认的按事实处理；主观的走交叉评审或人确认；周期性汇报
"确定/不确定"并抽检**。落地成三级判定，每级有明确的判据、执行者与不可越界的地方：

| 级 | 判据（机器可判） | 执行者 | 产出 | 禁止 |
| --- | --- | --- | --- | --- |
| **T1 可验证** | 条目里出现**本机可达**的文件系统路径（可带 `:行号`） | 脚本（`stat`，零命令零网络） | `confirmed` / `refuted` / `unknown` | 不得用"路径不存在"反推"事实错误"（见下面三条 unknown） |
| **T2 需交叉评审** | 无路径断言，但正文含"修正/取代/已过时"等**改动性声明** | 两个**不同源**的判定器（另一模型 + 结构化规则），不一致即升级 | `agree` / `disagree`（进人工） | 不得由**同一个**模型既生成又判定 |
| **T3 主观** | 既无路径断言也无改动声明 | 人，**按抽样** | 抽检记录 | 不得批量自动处理 |

**`unknown ≠ refuted` 的三条硬约束**（这是"维持准确性"的关键——把 `unknown` 当 `refuted` 会退役正确的记忆）：

1. **路径属于另一台主机或另一个 OS**（`/root/…`、`/volume1/…`、`C:\…`）⇒ `unknown(foreign_scope)`。
   这台机器上的存储混有 M1 与 M3 写的记忆，用户名相同，路径长得一样。
2. **路径是瞬时的**（`/tmp`、`/private/var/folders`）⇒ `unknown(ephemeral_path)`；长期记忆里存瞬时路径
   是**质量**问题（该写指针而不是路径），不是事实错误。
3. **父目录也不存在** ⇒ `unknown(ancestor_missing)`；只有**父目录存在而文件不存在**才判 `refuted(stale_path)`
   —— 那才证明"我们看的是同一棵树，而这棵树上没有它"。

**实测（2026-11-04，5,242 条）**：

| 级 / 判定 | 条目 | 占比 |
| --- | --- | --- |
| T1 `confirmed`（路径仍存在） | **486** | 9.3% |
| T1 `refuted`（同树上已消失） | **181** | 3.5% |
| T1 `unknown` | 310 | 5.9% |
| T2（改动性声明，无路径） | 277 | 5.3% |
| T3（主观，无断言） | **3,988** | 76.1% |

`unknown` 的构成：`ephemeral_path` 147 / `ancestor_missing` 124 / `foreign_scope` 81 / `unknown_scope` 54。

**这张表就是"处理方式"的答案**：机器能直接确认的只有 **12.8%**（486+181），其中 3.5% 已经陈旧；
**76% 的条目机器无从判断**。所以"按事实处理"必须做，但它只能覆盖一小部分；主力只能是
**写侧质量**（别把 `/tmp` 路径写进长期记忆）+ **评审/抽检**。反过来说：任何声称"自动清理了大部分记忆"
的方案，必然是在用文本相似度或模型猜测冒充事实。

**周期汇报与抽检协议**（`scripts/hygiene_verify.py report`）：

- 三类清单：`refuted`（**全量**纳入，按事实处理）、`unknown`（列出原因，不当作错误）、
  `unverifiable`（T2/T3，抽样）。
- 抽样是**可复核**的：`seed = sha256(周次 | 语料规模)`，同一周同一语料 ⇒ 同一批样本；
  同时抽 5 条 `confirmed` 作**对照**——如果对照里出现明显错误，说明验证器本身坏了，而不是记忆坏了。
- 频率：每周一次（与 P2 的节律作业同一条链），报告落 `hygiene-report-<ISO 周>.json`；
  连续两周 `refuted` 增长 >10% 即告警（说明写入侧在产生不可达指针）。

## 2.2 T2 判定器选型：kimi 做第一判、codex 做复核（2026-11-04 实测）

两台 CLI 都在本机可用，但**都不要单独当"事实来源"**，只当"另一个来源的判定器"。实测（同一对真实条目、
同一条提示词、`danger-full-access` 下）：

| 维度 | codex 0.166.0 | kimi 2.4.1 |
| --- | --- | --- |
| 冷启动（"只回答两个字"） | **41.9 s / 27,166 tokens** | **10.5 s**（约千级 token） |
| 单次判定（真实 A/B 对） | 44.6 s / 28,353 tokens | **12.3 s** |
| 结构化输出 | **`--output-schema` 强约束**，直接得到可解析 JSON | 无 schema；文本里夹版本横幅/思考行/续接提示，需正则抽取 |
| 只读 | `-s read-only` 原生；仓库外需 `--skip-git-repo-check` | prompt 模式不带权限标志，靠不使用工具 |
| 中文技术语义 | 可用 | **可用且更省**（语料 76% 是中文技术长句） |

推论（277 条 T2，按每条一次调用估）：

- codex 单条：**≈3.5 h / ≈7.8 M tokens**；kimi 单条：**≈55 min / 千级 token × 277**。
- 因此 codex 不能当第一判（27k tokens 一条的固定开销几乎全花在探索上），kimi 可以，但必须**批处理**（20 条/次）。

**选型决定**：

1. **第一判定器 = kimi**：批 20 条、严格"只输出 JSON 数组"、正则抽取 + 任一条解析失败即整批丢弃（**不得**用
   "猜它的意思"兜底）；只产出 `supersede_clause / independent / unclear` 这三类，不直接产出动作。
2. **复核与分歧裁决 = codex**：只在两类上跑——①kimi 判 `supersede*` 的（高风险）；②每周随机 10% 的
   `independent`（防"什么都没取代"的漏判）。用 `--output-schema` 拿结构化结果，便于对账。
3. **两者都不参与"写入"**：判定只是提议，落盘仍走 §9 的 plan/ledger，且人工确认。

**一个比选型更重要的发现（实测暴露）**：我给的提示词只有 `supersede | independent | unclear`，
两个模型都判了 `supersede`——但那条旧条目 E 是"需求分流工作约定"，被取代的只是其中**一句**关于
merge 权的约定。若照此执行，E 的其余内容会被一起退役。**所以必须加第四类 `supersede_clause` 并要求
判定器回指被取代的那一句**；入口级 `deprecate` 永远不能由 T2 判定直接产生。

## 2.3 更好的方案：先削量，再谈判定器（2026-11-04 实测）

2.2 的结论是"选 kimi 还是 codex"，但**真正的问题是为什么要一次判 277 条**。把语料拆开量之后，
模型判定的需求量被两层削掉。下面是**工具实测**（`python3 scripts/hygiene_cleanup.py plan --claims`，
可复跑），不是估算：

| 层 | 数量 | 处置 | 依据 |
| --- | --- | --- | --- |
| 声明（卡片词表，耐久轨道） | **329** | 逐条尝试解析目标 | `supersedes/取代/修正/更正/已过时/已废弃/过期` |
| 其中在 `daily/` | **189** | **不判** | 日刊是"那天发生了什么"，不是"当前事实" |
| 解析不到指代 | **305** | 标 `unresolved`，**不判、不动** | 正文声称修正却没给指针；模型也只会编一个目标 |
| **产出卡片** | **24**（位置 13 / 引号 11） | 人工过一遍，约 5–10 分钟 | 见下 |

**卡片为什么只有 24 张，而早先估过 47：** 第一版按"引号短语在同轨唯一命中"解析，出了 69 张，
里面混着 `o9cq807d…@im.wechat`、`{{DSH_SCHED_DELIVERY_KEY}}`、`有真实调用` 这类**非指代**
（它们"唯一命中"了无关条目——又是文本匹配不判别）。加三道闸门后降到 24：

1. **名称形状**：含 `@ { } < > | / \` 反引号的、纯 hex/数字的、短 ASCII 的，都不是名字；
2. **靠近声明词**（≤40 字符）——引号是这句话的宾语，而不是正文别处的引用；
3. **稀有度 `df ≤ 2`**：一个短语在语料里出现超过两次，就说明它是常用表达，不是名字。

三道闸门都是可测的（`_pointer_like` / `QUOTE_PROXIMITY` / `df_lookup`，各自有测试）。

**位置指代（"上一条"）不完美，但便宜**：13 张里有"上一条"实际指"上一次讨论"而非"前一条目"的情况
（如 c5 指向 B0.0 事故条目，真正要取代的是边界基线）。所以它仍进人工队列、只排在前面，
**不自动执行**。

**所以更好的方案是漏斗，不是判定器**：

1. **削量**（确定性）：排除 `daily/`、已有边、已退役 ⇒ 卡片候选从 329 降到"有指代的 24"。
2. **结构消解**（确定性、零模型）：位置优先、引号其次，三道闸门保证"指代像名字"。
3. **人工一次过完 24 张**：每张四选一 `整条取代 / 仅这一句 / 无关 / 看不出`；产出 24 条标注——
   以后任何判定器的**校准集**，白拿。
4. **305 条无指代**：周报单列，不动作；它是"写入质量"的指标。
5. **不用批量模型判定**：kimi 判 278 条约 55 min + token，而人工 24 张卡约 5–10 min 且更准
   （2.2 实测里模型把"只取代一句"判成了 `supersede`）。

**判定单位：按事项，不按条目**（2026-11-04 修正，用户指出"条目看不懂、有传承过程态、有几个事项一起的"）。
实测：21 张卡里 **19 张的旧条目**与 **20 张的新条目**都含 ≥3 个事项（`①②③` / 分号计数）。这类条目是
**过程日志**（"B0 推进""本轮修正""承接上一条"），问"整条是否被取代"根本没有答案。所以：

- 卡片现在是 **一个主题 + 两段话**：`「/opt/gw/conf.yml」这件事，哪个说法是当前的？`
  下面只放**该主题的两句**（`trim_around` 取主题词两侧各 100 字），全文折叠在"看全文"里；
- 主题键是**结构化**的（路径 > endpoint > 版本 > 反引号标识符 > CONST_LIKE > 「引号名」），
  两段话必须共享同一个键才出卡；共享不上就记 `unresolved_no_shared_subject`（实测 4 条），**不出卡**；
- 四选项改成**问话式**：`1 新的是当前（旧句作废） / 2 旧的仍有效（新条目可能写错） / 3 两件不同的事 / 4 看不出`。
  `2` 不是"无操作"——它说明**新条目可能错了**，因此产出 `flag_contradiction` 而不是空；
- **不再提供"整条取代"**：一句的判定不能退役整条。入口级退役要等"该条目的实质性分句都被判定取代"
  （派生规则，未实现）。

**复核面（怎么给意见）**——第一版只导出了一份 md，那只是"看得见"，不是"能回答"。现在的三个入口：

| 面 | 用法 | 适用 | 代价 |
| --- | --- | --- | --- |
| **对话里答** | `plan --claims --compact` 打出 25 行（每卡两行：旧/新），直接在会话里回 `c1=1 c2=2 …` | 现在这 25 张 | 最少，无新工具 |
| **答案文件** | 写 `c1=1` 每行一条，`--answers FILE` 读入；坏 id/坏取值 ⇒ **exit 2 并点名**，不静默丢弃 | 批量、可复核、可进 git | 一次编辑 |
| **本地 HTML 问卷**（已做） | `plan --claims --html FILE` 生成单文件页面：一次一张卡、键 1–4 记录并前进、←/→ 翻页、`u` 撤销、进度表可点跳转；答案存 localStorage（关掉可续），导出即 `c1=1` 文本，可直接喂 `--answers` | 想边看全文边判断 | 答案在浏览器里，导出后才进台账 |
| **交互终端** | 若要一条条按，运行者在 TTY 里跑（agent 会话里不做，避免挂住） | 数量大时 | 需 TTY |

答案的落点是**两份产物、都不写记忆**：`answers-<plan_id>.jsonl`（append-only 台账，含 plan_id 与周次）
与 `proposals-<plan_id>.json`（只对 `1/2` 生成 `add_supersedes_edge`，并标 `granularity: entry|clause`
与 `id_backfill_required`）。写者侧拿提案落 `[supersedes:id]`，`3/4` 不产生任何动作。

**模型该在什么时候上**：不是现在，而是**读侧惰性修复**——一次检索同时命中同一主题的两个版本时，
才需要判"哪条是当前的"，那时有 query 作上下文、一次 1–2 条、判完立刻有用。
若要走这条，先用这 24 条标注做校准集：量每个判定器的 precision/recall，再决定用谁、阈值多少
——**先量仪器，再选仪器**。

**写侧才是根治**（比任何判定器都便宜）：新记忆若含"修正/取代"+ 引号短语，写入时就能确定性解析出
目标并落 `[supersedes:id]`；解析不到就当场提示（人在场、只有一条）。积压因此不再增长，判定需求
从"每周 329"降到"每周 0–3"。

## 3. 理论：哪一条在什么条件下才成立

| 理论 | 关键式/机制 | 何时才相关 | 对本语料的裁决 |
| --- | --- | --- | --- |
| **BM25 / IDF 稀释** | `idf = ln((N−df+.5)/(df+.5))`；重复文档使 df 翻倍。N=7600 时 `ln7600−ln3800≈0.69`，稀有词权重降约 8% | **仅当重复内容真的进了索引** | **不适用**（重复≈0）。上一轮"去重能提升召回"的暗示撤回 |
| **AGM 信念修正 / JTMS** | 撤回要留 justification，删除不可逆；`supersedes` 就是 justification 边 | 事实会演化、需要解释"为什么变了" | **采用**：唯一同时保住 A 与历史的机制 |
| **双时间建模（Zep）** | `valid_at/invalid_at`（世界时间）vs `created_at/expired_at`（记录时间） | 需要"当时是什么"的点时间查询 | **采用 valid 区间**；`as_of` 查询延后 |
| **遗忘曲线（Ebbinghaus / 幂律）** | 指数 `exp(−t/S)` vs 幂律 `t^−d`；S 随成功召回增长（间隔效应）。MemoryBank 把 `−t/(5S)` 写成 `(−t/5)·S`，越常召回越早删 | 需要"让不重要的东西淡出" | **只用于排序与复审排期，永不用于删除**；公式带单调性测试 |
| **ACT-R 基础激活** | `A_i = ln(Σ_j t_j^{−d})`，`t_j` = 第 j 次召回距今时间，d≈0.5 | 需要同时编码"常用"与"最近" | **采用**为上下文选择的打分（比指数衰减更贴合间隔效应） |
| **上下文即缓存 / 预算背包** | `max Σ v_i x_i s.t. Σ s_i x_i ≤ B`，`v_i/s_i = P(need)·importance/size`；贪心近优 | 注入面有硬预算 | **采用**：替代"全量摘要注入" |
| **信息论去重** | 重复信息量≈0 bit 但占预算 | 重复占预算时 | 现在约占 0.04%，**不是杠杆** |
| **实体解析 / 别名** | 身份按内容/id，路径只是定位提示（与 `memory-retrieval-pipeline.md` §2.1 一致） | 同一实体多个名字 | **采用**：路径降级为 alias，id 升为身份 |
| **反思式压缩（Generative Agents）+ 可还原压缩（Manus）** | 压缩必须保留指针/锚点，否则不可逆 | 长尾证据（daily）需要瘦身 | **采用**：摘要带稀有锚点，能回读原文 |

一句话：**准确性靠"撤回"，可触达靠"选择"**。把这两件事混成一个"清理"动作，就会重演 MemoryBank 的错误
（用衰减去删除）或我上一轮的错误（用路径计数去判重复）。

## 4. 对三项待拍板的回答

| 问题 | 建议 | 依据 | 反着做的代价 |
| --- | --- | --- | --- |
| 14 组"重复轨道"怎么办 | **不删、不合并**；登记为 alias 并加门禁（已实现） | 同 inode = 一份数据两个名字；写穿任一路径都落到同一文件 | 删掉别名 → 该 cwd 项目记忆不可达（A 不变、R 断崖） |
| 131 条自述取代 | **只处理能机械判定的 4 条**（引号短语 + 同轨 + 时间更早 + 目标仍 active），人工批量确认；其余**不做**，改为写侧强制 `[supersedes:id]` + 惰性修复（旧条目被检索到时才修） | 可机械判定率 3%；错误 deprecate 直接伤 A | 按文本批量退役 → 误退役（A 反而降，且不可解释） |
| `daily/` 是否设 TTL | **先摘要、后 TTL**：30 天原文 → 月度摘要（含稀有锚点与原文指针）→ 原文进归档目录 | 压缩必须可还原；日刊是证据面 | 直接删/直接压 → 丢证据且不可回读（R 不可逆下降） |

**惰性修复**值得展开：不必一次修完 131 条。命中一条"旧条目被检索到且它有个更晚的兄弟条目"时，才生成一条
`supersede` 提案。按使用频率付费，避免了为 90% 从不被检索的条目付人工成本 —— 这正是 ACT-R 激活度该管的事，
而不是"按日期全量扫"。

| 步 | 动作 | 目标 | 风险 | 回滚 |

P1 之所以排在 P2 前面：**没有身份就没有结构**。131 条里只有 2 条带 `[supersedes:]`，而插件在没有 id 的条目上
做 `deprecateEntry` 时会**就地补发 id** —— 说明"先有 id"是这套机制的隐含前提，缺它会让每一次退役都产生
"新 id"，跨设备/跨版本无法对齐。

## 6. 度量与门禁（每次改动都要过）

```bash
python3 scripts/hygiene_scan.py --corpus dsh-md:~/.dsh/memories          # coverage / context_face 必须被报出
python3 scripts/hygiene_cleanup.py plan                                 # actions 应为 0（或极少数、全部可解释）
python3 scripts/hygiene_scan.py --self-test && python3 scripts/hygiene_cleanup.py self-test
python3 -m pytest tests/unit/test_hygiene_scan.py tests/unit/test_hygiene_cleanup.py -q
```

- **无回归门**：冻结需求集 Hit@5 变化 ≤1pp；准确性抽样中"过期当最新"计数不得上升。
- **预算门**：`context_face.chars` 不得随清理上升；每加一条摘要必须能指出它替掉了什么。
- **沉默即告警**：扫描/计划作业 6h 无新增即 `hygiene_stale`（本仓已有两次"探针静默被读成正常"的教训）。

## 7. 明确不做的

- 不以"库变小"为目标（空间轴已有 `retention-policy.md`，且收益一次性）。
- 不用文本相似度做退役判据（本仓 87/87 回测失效）。
- 不做无人确认的批量淘汰；不原地改写旧正文；不删 `daily/` 证据。
- 不把"别名"当"重复"，也不为省事去删别名目录。
